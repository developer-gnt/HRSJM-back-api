### Design decisions already applied (documented in test-scenarios.md "per design")
- Registration auto-issues access+refresh tokens; initial role MEMBER (roles table + baseline seeds created now as the Phase 2 integration point).
- Refresh tokens are opaque random strings stored as SHA-256 hashes, rotated on every refresh (old token revoked atomically, `replaced_by` linked).
- Logout takes the refresh token in the body and is idempotent.
- Forgot-password returns a generic message (no user enumeration); delivery channel is TBC per BRD, so the raw reset token is returned **only outside production** for manual testing.
